First launch

What to expect the first time.

  1. Open it

    Open the DMG and drag Cheerio to your Applications folder, then open it from there. The build is signed and notarized, so it opens the way any app does — no warnings, no extra steps. Run it from your Downloads folder instead and macOS starts it under app translocation, a read-only mount where Cheerio can't update itself.

  2. Grant the microphone

    Asked once, the first time you record. If you refuse, macOS won't ask again and you'll need System Settings → Privacy & Security to change your mind.

  3. Wait once for the speech model

    macOS downloads the transcription model for your language the first time you start a recording. It happens once per language.

  4. Updates take care of themselves

    Cheerio checks GitHub Releases once a day for a newer version and offers it to you. That check, and the download if you accept an update, are the only requests the app itself makes — nothing about you or your Mac goes with them, a check never starts while you're recording, and you can turn it off or switch it to install automatically in Settings → Updates.

  5. Enroll your voice

    In Settings → Participants. Speaker identification only returns names for voices it has heard before, and samples need at least 30 seconds — shorter ones measurably cause one person to be split across two speakers.

  6. Put headphones on

    Until echo cancellation lands, meeting audio playing out loud gets picked up by your microphone and the transcript says everything twice.

From source

Build it yourself.

You'll need macOS 26, Xcode 26, and XcodeGen (brew install xcodegen). The Xcode project is generated rather than committed.

git clone https://github.com/ObviosCo/cheerio.git && cd cheerio
./Scripts/bootstrap.sh
open Cheerio.xcodeproj

bootstrap.sh checks your toolchain, downloads the ~93 MB speaker model that isn't committed to the repo, and generates the Xcode project — in that order, because the project file references the model and generation fails without it. Every step is safe to repeat. Then build and run the Cheerio scheme.

Before you run it

Set PRODUCT_BUNDLE_IDENTIFIER in project.yml — it's the placeholder app.cheerio.mac, and it overrides options.bundleIdPrefix, so changing the prefix alone leaves you building with the placeholder. Change both.

Re-run bootstrap.sh after adding or removing source files, or the build won't see them. Full instructions are in the README.

Licensing, in one paragraph

Cheerio's source is MIT. It depends on FluidAudio (Apache 2.0) and bundles NVIDIA's Sortformer model (© NVIDIA, CC BY 4.0, Core ML conversion by FluidInference). The model is fetched by a script rather than committed, which keeps the source tree MIT while a built app bundles the CC-licensed model.
