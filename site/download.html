Download Cheerio

Cheerio isn't on the Mac App Store, and can't be — the App Sandbox has to be off for it to capture system audio at all, which makes the store unavailable. So it comes from here.

What you need
macOS26 (Tahoe) or later
HardwareApple Silicon. There is no Intel build — the speaker model runs on the Neural Engine.
PermissionsMicrophone and system audio recording. Calendar is optional and only affects meeting titles.
DiskSpace for retained audio, which you control — the default keeps seven days.

First launch

What to expect the first time.

  1. Open it

    Drag Cheerio to your Applications folder and open it. A notarized build opens the way any app does. Today's builds are ad-hoc signed, so macOS will warn about an unidentified developer once: right-click the app and choose Open, or approve it under System Settings → Privacy & Security. Each release's notes say how that build is signed.

  2. Grant the microphone

    Asked once, the first time you record. If you refuse, macOS won't ask again and you'll need System Settings → Privacy & Security to change your mind.

  3. Wait once for the speech model

    macOS downloads the transcription model for your language the first time you start a recording. It happens once per language, and it's the only thing Cheerio ever causes to be fetched.

  4. Enroll your voice

    In Settings → Participants. Speaker identification only returns names for voices it has heard before, and samples need at least 30 seconds — shorter ones measurably cause one person to be split across two speakers.

  5. Put headphones on

    Until echo cancellation lands, meeting audio playing out loud gets picked up by your microphone and the transcript says everything twice.

From source

Build it yourself.

You'll need macOS 26, Xcode 26, and XcodeGen (brew install xcodegen). The Xcode project is generated rather than committed.

git clone https://github.com/ObviosCo/cheerio.git && cd cheerio
./Scripts/bootstrap.sh
open Cheerio.xcodeproj

bootstrap.sh checks your toolchain, downloads the ~93 MB speaker model that isn't committed to the repo, and generates the Xcode project — in that order, because the project file references the model and generation fails without it. Every step is safe to repeat. Then build and run the Cheerio scheme.

Before you run it

Set PRODUCT_BUNDLE_IDENTIFIER in project.yml — it's the placeholder app.cheerio.mac, and it overrides options.bundleIdPrefix, so changing the prefix alone leaves you building with the placeholder. Change both.

Re-run bootstrap.sh after adding or removing source files, or the build won't see them. Full instructions are in the README.

Licensing, in one paragraph

Cheerio's source is MIT. It depends on FluidAudio (Apache 2.0) and bundles NVIDIA's Sortformer model under the NVIDIA Open Model License. The model is fetched by a script rather than committed, which keeps the source tree MIT while an app built from it bundles an NVIDIA-licensed model. Check that licence before redistributing a build.
