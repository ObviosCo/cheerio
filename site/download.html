First launch

What to expect the first time.

  1. Open it

    Open the download and drag Cheerio to your Applications folder, then open it from there. The build is signed and notarized, so it opens the way any app does. No warnings, no extra steps. Run it from your Downloads folder instead and macOS starts it under app translocation, a read-only mount where Cheerio can't update itself.

  2. Grant the microphone

    Asked once, the first time you record. If you refuse, macOS won't ask again and you'll need System Settings → Privacy & Security to change your mind.

  3. Wait once for the speech model

    macOS downloads the transcription model for your language the first time you start a recording. It happens once per language.

  4. Updates take care of themselves

    Cheerio checks GitHub Releases once a day for a newer version and offers it to you. That check, and the download if you accept an update, are the only requests the app itself makes. Nothing about you or your Mac goes with them, a check never starts while you're recording, and you can turn it off or switch it to install automatically in Settings → Updates.

  5. Enroll your voice

    The walkthrough asks for this on first run, and Settings → Participants is where you add everyone else. Speaker identification only returns names for voices it has heard before, and samples need at least 30 seconds. Shorter ones measurably cause one person to get split across two speakers.

  6. Put headphones on

    This is a setup step rather than a preference. Cheerio records your microphone and your Mac's output separately; with the meeting playing out loud, the microphone hears it too, both streams end up with the same words, and the transcript says everything twice. Headphones remove it completely, and echo cancellation on the mic input is being built so it stops being a step.

If something goes wrong

The FAQ covers what gets uploaded, how many people it can tell apart, and what happens if you stop using it. Each version's known issues ship alongside it in the release notes. Anything else (including anything that looks like a bug) belongs in the issue tracker. We read it.
